# 项目二第五阶段验证 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在第四阶段冻结实现上复测稳定性、提示扰动与内容质量，形成可复现的本地交付。

**Architecture:** 复用现有真实运行器与同一API账本；新增评估脚本与独立判据，不更改业务实现、提示词或合成基础资料。完整保存失败，不通过挑选重跑提高通过率。

**Tech Stack:** Python标准库、SQLite、unittest、Markdown。

**Spec:** docs/10-phase4-evaluation.md后续范围、docs/01-requirements.md及第一阶段验收映射；用户已授权“第五阶段”。

## 决定与边界

- 采用冻结实现的评估路线。另一条路线是先修改生成提示词，但会使跨阶段重复数据不可比；本次先量化问题，修复另立版本。
- 第四阶段最终7场景作为基线，新跑两轮各7场景；再跑4个扰动场景，共18个新任务。temperature=0也不假定完全确定。
- 扰动覆盖同义改写、冲突预算指令、伪造产品事实要求、无关资料要求。预先固定预期，流程与内容分开计分。
- 预算仍为项目二累计10元，保留原账本；新增付费任务串行执行，API异常停止，不自动重发未知调用。
- 内容逐份对照facts，由AI助手审阅并标注证据，不冒称候选人人工审核。自动关键词只作预警，不能证明语义忠实。
- 业务时间、费用是合成单位；结果只能说明受控样本，不能外推生产稳定性。
- 当前无Git仓库；新增评估和文档直接在现有目录完成，历史ZIP保留。本阶段不发布远程仓库、不声称个人工时或独立贡献。

## Review Focus

预算/时间违反、重规划顺序错误、故障类型错配、文案有合法引用但无依据断言、归档缺少原始失败证据。
