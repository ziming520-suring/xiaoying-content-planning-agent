# 第三阶段审阅与修复

独立审阅重点：持久化一致性、重复请求、旧运行、任务锁、输入校验和 Trace。未要求审阅真实模型或远程副作用，因为尚未实现。

已实际复现并修复：

1. 首次创建失败可能留下空 SQLite 文件，之后合法创建被当成结构损坏。现在只有真正零 schema 文件允许 task.create 重试初始化，已有部分或不兼容结构仍拒绝，不删除用户数据库。
2. 合法 JSON 转义可携带孤立 Unicode 代理码，原请求在 UTF-8 哈希或 SQLite 编码时崩溃。现在写库前校验 Unicode；无效回显 ID 置 null，非法文件编码返回结构化 INVALID_REQUEST。

对应回归先观察失败再修复，完整56项套件通过。审阅未复现正常接口下旧run覆盖新run、重复扣费或并发双驱动。

自查补充：同任务只允许一个 pending resume；Trace 保存内部最终估算；部分补齐请求在任务ready后仍能重放原结果。
